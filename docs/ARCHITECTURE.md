# Architecture and boundaries

The project builds **two layers**:

1. **Managed C# payload** compiled with the .NET 8 Roslyn compiler against the user's local Solasta/Unity assemblies plus vendored Harmony.
2. **Windows x64 `winhttp.dll` proxy/loader**, built with MinGW-w64 from the bundled and modified Unity Doorstop implementation; it embeds the managed payload and forwards normal WinHTTP imports.

The build entry point is `build-windows.ps1` → `source/build.py`; generated artifacts go into `build/`. Do **not** commit game DLLs or output generated by the build.

## Main components

| Source | Responsibility |
| --- | --- |
| `CoopView.cs` | Entry point, update loop, hotkeys and F8 settings |
| `PhotonTransport.cs`, `ConnectionRetry.cs`, `RetryBudget.cs` | Network event helpers, protocol choice, acknowledged safe JoinRoom retry |
| `ObserverHud.cs`, `ObserverPreview.cs` | Teammate UI preview with action guards |
| `HoverRange.cs`, `CameraZoom.cs` | Target range and camera zoom |
| `TravelShare.cs`, `TravelWire.cs`, `AutoFastTravelVote.cs` | Shared travel preview and fast-travel vote acceptance |
| `AutoFollow.cs`, `HostMoveShare.cs` | Movement of local heroes, waypoint capture and Photon event sharing |
| `LootShare.cs`, `ItemTransferRange.cs` | Native shared loot UI and interaction distance adjustments |
| `CombatSpeed.cs` | Visual animation playback speed changes, with restoration outside battle |
| `DiagnosticsLog.cs`, `RuntimeDiagnostics.cs`, `LogLocation.cs` | Diagnostics, network/turn-state observations and logs |
| `HarmonySupport.cs` | Harmony patch installation helpers |

## Design constraints

- **Avoid native game ownership manipulation:** local players should control only their own heroes.
- **Loot interactions are gameplay mutations:** the receiver uses native Solasta loot mechanisms rather than duplicating inventory changes through custom RPCs. Host-side checks may still refuse them.
- **Do not patch Unity global time:** combat speed acceleration is per-animation, not `Time.timeScale`, network timeouts or simulation time.
- **Do not blindly retry CreateRoom:** a room may already exist after a game server timeout.
- **Auto-follow is a movement helper, not a teleport:** a valid path and gameplay state must exist.
- **Screenshot-based loot streaming and F11 are removed** because this previously destabilized cooperative sessions.

## Validation levels

- Static source/sanity tests do not prove that C# compiles or that Unity API names match the installed game.
- Compilation against owned Solasta assemblies does not prove compatibility of gameplay patches at runtime.
- A two-player test with matching mod versions and backed-up saves is required before a feature can be labeled verified.

Commit history is **reconstructed** from packaged source versions and is intended to make major features discoverable, not to impersonate the original development timeline.
